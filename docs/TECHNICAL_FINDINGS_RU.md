## 1. Исходные данные OpenAI не равны структуре экрана

Экспорт описывает историю с `mapping`: узлы с `parent`, `message` и метаданными. Часть узлов — `message: null` или промежуточные сервисные `thoughts`, `reasoning_recap`; несколько узлов могут быть в разных ветках. Следовательно, правильный HTML нельзя восстановить простым перебором сообщений по времени.

Наша система ориентируется на дерево, роли и типы содержимого. Исходные сообщения не переписываются.

## 2. Главный механизм привязки медиа

`library_files.json` может содержать: `file_id`, `file_name`, `file_size_bytes`, `state`, `created_at`, `origination_message_id`, `origination_thread_id`, `image_gen_generation_id`. Не все поля гарантированы у каждой записи.

**Сначала устанавливаем существование байтов**, затем — место. `file_id` → реальный физический файл вида `file_ID.dat`, `file_ID.png` либо запись в манифесте. Сигнатура помогает определить расширение, SHA-256 проверяет эквивалентность. Простое совпадение размера не является доказательством идентичности.

Для связывания с перепиской строятся как минимум:

- индекс `message.id` и ключей `mapping`;
- индекс `message.metadata.parent_id` — включая ID отсутствующих промежуточных событий;
- родительские связи `mapping.parent`, учитывая альтернативные ветки;
- временные индексы пользователей/ассистентов, строго как дополнительное, слабое основание;
- прямые упоминания `file_id`, `sandbox:/mnt/data/...` и других ссылок.

Приоритетная модель — `manual` → прямое упоминание/`exact` → граф через виртуальный ID/`inferred` → осторожные временные эвристики/`inferred` → `synthesized` при генерации без видимого ответа → `unplaced`. Неизвестные связи нельзя «улучшать» фиктивным ID.

**Ключевой пример графа:**

```text
Library.origination_message_id = VIRTUAL_ID
                                  │
                                  ▼
служебное сообщение assistant
  metadata.parent_id = VIRTUAL_ID
  mapping key = SERVICE_ID
                                  │
                                  ▼
видимый ответ assistant/text
  mapping.parent = SERVICE_ID
```

Слабость эвристик: по прошлому аудиту двух чатов 232 `inferred` включали 104 графовых сопоставления и 128 преимущественно временных. По времени могут быть ошибки при альтернативных ветках; пользователь должен проверять спорное расположение.

## 3. `synthesized`: картинка есть, но финального ответа нет

Некоторые действия генерации заканчиваются картинкой в Library и служебным шагом ассистента, но в `mapping` **нет отдельного видимого финального текста**. Выдумывать текст или исторический message ID нельзя. Вместо этого отображается синтетическая карточка ассистента после исходного запроса. Статус такой связи — `synthesized`, а не `exact`.

В предшествующей проверке двух чатов было создано 20 таких карточек. Все они использовали и структурную связь с пользовательским запросом, и время. Если доказательств недостаточно, файл остаётся в сводке.

## 4. Полный список файлов как основной реестр UI

Вместо подмены `generated_files.html` новая функция **подключает интерфейс прямо к существующему списку**, не меняя его строки и порядок. Для каждой отсутствующей записи выделяется уникальный ключ на основе ID или исходной ссылки и чата. При восстановлении обновляются статус, локальный файл и связанные чаты. Один и тот же файл может использоваться несколькими ссылками или встречаться в нескольких диалогах.

В исходном проекте прежняя страница содержала 7 237 строк, в отличие от ошибочного сокращённого списка на 200; этот дефект был исправлен.

## 5. Восстановление ссылок по РОЛИ исходного Markdown

Один файл может быть дважды или трижды использован в ответе: как `![превью](...)`, как `[Скачать](...)`, как дополнительный документ. Когда PNG отсутствует, конвертер оставляет текстовое предупреждение без исходного URL. Заменять предупреждения только по подписи или порядку нельзя.

`recovery_source_links.py` читает доступный исходный шард, извлекает роль (**image** или **download**) и подпись каждого обращения и выполняет замену только при однозначном сопоставлении. Если прямых доказательств нет, используется ограниченный безопасный запасной способ либо файл остаётся в сводке. Восстановленная картинка должна находиться внутри `<div class="body">`, а не становиться третьим элементом CSS-grid `<article>`.

При исправлении ранее восстановленных файлов исходный HTML хранится с суффиксом `.before_recovery.html` — это позволяет заново применить реестр, не наслаивая карточки друг на друга.

## 6. Независимость сервера и HTML

`serve_archive.py` выдаёт HTML через `127.0.0.1`, используя случайный URL-токен; скрипты кнопок копирования, QUESTIONS и переключателей **инжектируются в ответ сервера**, а не переписывают тысячи чатов. Контент чата открыт в изолированном iframe. Для функций браузера, которым мешает непрозрачное происхождение iframe, предусмотрен альтернативный маршрут/механизм.

**Важно:** проверка `image_paths_summary.txt` подтверждает только ссылки, уже присутствующие в HTML; она не может обнаружить изображения, вообще не вставленные в страницу.

## 7. Формулы и Intelligent UI

Математика остаётся на локальном MathJax (`viewer/mathjax-tex-svg.js`). Исходник UI сохраняется в `dil_sources/*.txt`. Визуальный режим использует статический DIL-рендерер, а режим OFF — читаемую Markdown-версию. При ошибке визуализации можно скачать полный исходный DIL.

Наша реализация поддерживает часть компонентов (`box`, `row`, `grid`, `text`, `badge`, `svg`), ограниченные `{#each}`/`{#if}` и подстановки. Это **не оригинальный закрытый движок**; сложные действия, live данные и исполняемые программы не запускаются. В отдельных `codeblock` и вложенных элементах до сих пор возможны буквальные `**...**` — известный дефект.

## 8. Полезные отчёты и восстановимость

- `message_file_bindings.csv`: кто, куда, с каким основанием и уверенностью привязан.
- `unplaced_library_files.csv`: не удалось выбрать сообщение.
- `library_integrity_report.csv`: физическое содержимое vs Library.
- `generated_files_report.csv`: упоминания и статусы файлов в истории.
- `recovered_files.json`: ручное дополнение с `file_id`, именем ассета, SHA-256, положением и связанными чатами.
- `ChatGPT_Binding_Overrides.json`: ручное явное исправление привязки (обязательно проверяйте `conversation_id` и `message_id`).

**Сохраняйте в резервной копии** обе папки `ChatGPT_Local_Archive/` и `ChatGPT_Generated_Files/` вместе с исходными JSON. Это важнее, чем хранить только исходный ZIP программы.
